# Changelog

This file records every notable change to GrokChat: what changed, and why. It follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions will follow [Semantic Versioning](https://semver.org/) from the first release to `main`.

## [Unreleased]

### Added

- **The dashboard and the OAuth connect flow** (GROKCHAT-12, plan §3.4, §3.5 and §7.1 PR 7):
  - pages, server-rendered by Hono with vendored htmx 2.0.11 (SHA-384 pinned, served by the Worker): backlog (filter by account and status), calendar (seven UTC days), post detail with edit (media kept), approve, reject, cancel, delete and reschedule (with the "I checked X" confirmation for NOT_FOUND), accounts (kill switch, disclosure, policy, NEEDS_RECONNECT shown, connect and reconnect), personalities, metrics, costs, R2 media usage against the guard and the free allowance, audit;
  - login with PBKDF2-SHA-256 at 100,000 iterations (the Workers maximum, U19) behind the `LoginThrottle` (per client IP and one global key); a 12-hour `__Host-` session cookie signed with HMAC-SHA-256 (`SameSite=Strict; Secure; HttpOnly`); a CSRF token per session plus an exact `Origin` check on every non-GET route; CSP, `Referrer-Policy: same-origin` (`no-referrer` only on the OAuth callback and finish, since a form POST from a `no-referrer` page sends `Origin: null`), `no-store`, no framing; 503 until the three settings are present;
  - the OAuth connect flow: `POST /oauth/x/start` behind the session (PKCE S256 and a single-use state through `OAuthStateStore`, plus a signed ten-minute intent cookie bound to the session and the state), `GET /oauth/x/callback`, which only bounces, and `GET /oauth/x/finish`, behind the session, which completes it;
  - use cases the dashboard needed: `login` (with a `PasswordVerifier` port), `listAccounts`, `listPersonalities`, `getMediaUsage`; `PartView` now carries its staged media ids;
  - framework-free controllers, presenters and view models in `interface_adapters/dashboard` (Stryker 100%); drivers in `frameworks/web` (WebCrypto PBKDF2, HMAC cookies, random ids); `main.ts` wires it per `env` on the D1 repositories (GROKCHAT-8), the account's Durable Object through `AccountObjects` for deletes and a connect's tokens, and the X OAuth connector (GROKCHAT-9, audited, built only when a connect starts or finishes, so missing `X_CLIENT_ID`/`X_CLIENT_SECRET` fail there); the dashboard reuses the system clock and WebCrypto PKCE of GROKCHAT-8 and GROKCHAT-9 instead of its own copies;
  - tests: R11 (missing session, replayed, expired and foreign state, a different X user on reconnect), R12 (no token, wrong token, wrong or missing Origin: 403; throttle: 429), and the logs never holding `Authorization`, `Cookie`, the password, the session or the callback's code and state;
  - **Why:** the owner runs every account from the dashboard: review and approve, the kill switch, the disclosure gate, connecting accounts, and the cost and R2 numbers that keep GrokChat on the free plan (plan §0, §2, §3.5).
- **X API drivers** (GROKCHAT-9, plan §3.5 and §7.1 PR 4), in `src/frameworks/x_http` and `src/frameworks/x_auth`:
  - `fetch` drivers for `XPublisher` (create, delete), `XMediaUploader` (one-shot upload for photos; chunked initialize/append/finalize/STATUS for GIFs), `XMetricsReader` (public and non-public metrics, ≤ 100 ids, more refused before sending), `XOwnTimelineReader` (`GET /2/users/:id/tweets` with `start_time`; the oldest posts after `since`, oldest first, now pinned by the port's contract and the fake), all through one `XApiClient` that takes the account's token from `TokenProvider` (never a token argument, A1);
  - OAuth: the PKCE connector (authorize URL, code exchange with HTTP Basic, `/2/users/me`), the refresh call `RefreshingTokenProvider` uses (60 s, never cut short), WebCrypto PKCE (RFC 7636's S256 vector), and the config parsed from `X_CLIENT_ID`, `X_CLIENT_SECRET`, `GROKCHAT_PUBLIC_ORIGIN`;
  - error mapping: a pre-send error → retryable; a timeout, a dropped or refused connection (workerd cannot tell them apart) or a 5xx → unknown; 429 with its app or user window; 401 and an auth 403 → needs reconnect; a content 403 (duplicate or forbidden content) → rejected, through two new `XFailure` kinds, `content_refused` and `no_token`;
  - cost and audit decorators for the OAuth calls (refresh: $0 `oauth` + `x.oauth`, recorded after the result so it never delays persisting a rotated token; code exchange: audited); the other X calls keep their entries in the run services (`XCallRecorder`, the create inside `commitPart`'s batch);
  - the reconcile check and the token step budget one more lookup and the refresh's two records (`RECONCILE_CHECK_COST` 4, `TOKEN_STEP_COST` 4 Cloudflare calls);
  - tests: the X port contracts run against the fakes and the drivers (an X emulator behind a fixture transport, bodies and headers shaped from docs.x.com and the U1/U14 spikes); wire tests for every request and mapping; fast-check properties (GIF segments, timeline order, rate-limit windows, base64url); a `live` suite (`npm run test:live`) skipped unless `GROKCHAT_LIVE=1`, for the owner only, under a spending limit;
  - review fixes: `MeteredTransport` spends one external subrequest per X or token request, so a long thread with GIFs or a large reconcile or metrics batch yields instead of hitting workerd's subrequest limit (U16); `XApiClient` asks for tokens against the invocation's real deadline, and reconcile and metrics take the token step first (`TokenStep`), so a refresh that does not fit yields before any call to X (N1); the refresh's reserved time is now its 60 s timeout (`TOKEN_STEP_COST.millis`), checked only when a refresh is needed;
  - the drivers are not yet wired into the account's Durable Object: its factory (`buildAccountServices`, GROKCHAT-8) builds one graph per object, while the X drivers need one per invocation around its `BudgetMeter`, so its X ports stay `X_UNAVAILABLE`; reconcile and metrics there take the token step (`TokenStep`);
  - **Why:** PR 4 replaces the fake X with real drivers that must pass the same contracts, so the publishing rules proved on stubs in PR 2 hold against X's real responses (plan §7.1).
- **D1, Durable Object and R2 drivers** (GROKCHAT-8, plan §3.5 and §7.1 PR 3):
  - `migrations/0001_initial.sql`: every D1 table, the unique `(bot_id, idempotency_key)` index, the plan's indexes, and the indexed forms the per-minute queries need (`posts.due_at`, a `post_parts` index table with `attempt_at` and `metrics_next_at`); a D1 repository for every D1 port in `src/frameworks/d1/`;
  - `save` and `commitPart` are one batch that starts with the raising `version_guard` insert and ends by emptying it, so a stale version or lifecycle writes nothing (U15, R21); `commitPart` now takes `expectedLifecycle` (the minor carried from PR 2);
  - the `AccountPublisher` Durable Object: the RPC surface (`AccountPublisherObject`), every method's errors mapped so a throw never resets it, one object per account; `main.ts` builds its graph (`buildAccountServices`) with the two ordered promise-chain mutexes; `AccountObjects` is the Worker's client, which never retries a rejected call; X ports are `X_UNAVAILABLE` until PR 4, so nothing is sent;
  - the token store in the object's storage, sealed with AES-256-GCM under `GROKCHAT_TOKEN_KEYS` (key ids, account-bound, re-sealed under the newest key on load), with the REFRESHING marker in the same value, so clearing it and writing the rotated tokens is one atomic put;
  - the R2 media store (`grokchat-media`); the quota guard and staged-media cleanup proved on D1 and R2;
  - tests: every D1/DO/R2 driver passes its port's contract in workerd; a fast-check differential test of the D1 reader against the stub; bounded rows read per per-minute query (I9); concurrency tests through the real object with negative controls: R1, R3, R4, R14, R17, R18, R19, R20, R21;
  - `npm run mutate:changed`: Stryker on the changed files of its mutate set, for the fast loop.
  - review fix: a publish-lock waiter stops waiting at its deadline even while the holder still runs (plan §3.3 #1, §3.1.1), on real timers in the object (`SystemClock`) and on the manual clock in tests; its slot is freed when the holder releases, so the lock order holds. A `publishNow` queued behind a long `publishDue` now returns not-run on time, its post unchanged, instead of outlasting xAI's 60 s limit;
  - **Why:** the use cases proved on stubs in PR 2 now run on the storage they will use in production, under the same contracts, with the concurrency risks of plan §4 shown to fail without their guards.
- **Entities, ports and every use case, on in-memory stubs** (GROKCHAT-7, plan §3.1–§3.3 and §7.1 PR 2):
  - entities: identity and `authorize`; accounts and the posting policy; `validatePart` and URL detection through twitter-text 3.1.0 in `entities/text`, checked against the upstream conformance YAML (U13); the post model with the §3.1.1 transition table, `derivedStatus` and `missed`; `checkPublishable` and `nextAllowedAt` across time zones and DST; `mapXOutcome` (401/403 → needs reconnect; app-scope 429 as its own outcome); `refreshOutcome` with the stored-token check (U1, U14); `estimateCost` (scheme URL $0.20, bare domain $0.015, U4); `metricsDue`; `redact`; the R2 quota and cleanup policies; the media URL (SSRF) policy; `Budget` with the shared 1,000 Cloudflare-service pool and 50 external fetches (U16);
  - every port of §3.2 with entity types only, plus `TokenStore`, `XTokenRefresher`, `SingleFlight`, `MediaUsageRepository`, `ContentHasher` and `PkceGenerator`; an in-memory stub for each in `src/frameworks/memory/` (the DO's promise-chain mutex, a fake X with scripted outcomes, U1's single-use token rotation);
  - use cases, one folder each: create (idempotency, the inline 10 s publish), edit, cancel, approve, reject, reschedule, media staging from a URL and by upload, the three cron ticks (fan-out ceiling 200), delete, the read side, and the admin and OAuth connect flows; run services: `PublishPost` (recovery under the publish lock, then token first, worst-case budget, ReservePart, create, one guarded commit), the refreshing token provider, reconcile, metrics, the X gateway, media cleanup;
  - tests: the transition table exhaustively, fast-check properties (cap, gap, quiet hours across zones and DST, `missed`, `metricsDue`, `estimateCost`, `redact`), every interactor, invariants I1–I9 with a no-lock negative control and DO-reset injection, a contract suite per stateful port (run in workerd), and a compiler-API scan of port signatures; Stryker 100% on the pure layers;
  - `yaml` 2.9.1 as a development dependency, to read the upstream conformance files (decision record).
  - review fixes: a first part held back by the gate or by X's `retryAt` stays SCHEDULED with that not-before time, and `missed` counts from max(`publishAt`, not-before) + grace, so queued posts are no longer lost and a 429 is not retried every tick; reconcile compares text with every URL masked and trailing links dropped, so parts with URLs, bare domains or media match X's t.co-rewritten `text`; fast-check properties for `missed`;
  - **Why:** the domain and its rules are proved on stubs before any driver exists, so PR 3 (D1 and the Durable Object) and PR 4 (X) only add drivers that must pass the same contracts (plan §7.1).
- **The TypeScript skeleton on Cloudflare Workers, with every gate** (GROKCHAT-6, plan §5 and §7.1 PR 1):

  - Vitest 5 in plain Node and in workerd (`@cloudflare/vitest-plugin` with local D1, Durable Object and R2), istanbul thresholds lines 90 and branches 90, each separate; Stryker on the pure layers with break threshold 100; licence allowlists with the `twitter-text` override; `npm audit --omit=dev`; `npm run check` runs them all;

  - decision records: the TypeScript exception, Cloudflare-only hosting, tooling and gates, and one per runtime dependency (`@modelcontextprotocol/sdk`, zod, hono, htmx, twitter-text); `CONTRIBUTING.md`; `.dev.vars.example` (names only).
